# Requirements Table

## Problem Statement #59
### Community Lost & Found Matching Network


| ID          | Type               | Description                                                                                                                  | Priority | Acceptance Criteria                                                                                                                       | Reason                                              |
| ----------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| **FR-1**  | Functional         | Allow Finder/Owner to create Lost/Found reports with item details, location, date and optional image.                        | High     | **Pass:** Valid report receives a unique ID and Active status.<br>**Fail:** Invalid or incomplete reports are rejected.          | Reports are the primary input to the system.        |
| **FR-2**  | Functional         | Extract visual/text tags such as category, colour, brand and keywords from item information and images.                      | High     | **Pass:** Relevant tags are extracted and associated with the report.<br>**Fail:** Irrelevant or missing tags are assigned.      | Tags improve matching accuracy.                     |
| **FR-3**  | Functional         | Match Lost and Found reports using category, tags, colour and geographical proximity.                                        | High     | **Pass:** Compatible reports receive a match score.<br>**Fail:** Incompatible reports are not matched.                           | Automated matching speeds up item recovery.         |
| **FR-4**  | Functional         | Allow Finder to create private ownership questions and require claimants to answer them before contact details are revealed. | High     | **Pass:** Correct answers allow verification.<br>**Fail:** Incorrect answers prevent contact access.                             | Prevents fraudulent claims.                         |
| **FR-5**  | Functional         | Allow Community Admin to review, approve, reject, remove reports and manage disputed claims.                                 | Medium   | **Pass:** Authorized actions correctly update the report status.<br>**Fail:** Unauthorized users cannot modify reports.          | Maintains platform reliability and prevents misuse. |
| **NFR-1** | Security & Privacy | Protect verification questions, answers and contact information from unauthorized access.                                    | High     | **Pass:** Protected information is inaccessible before verification.<br>**Fail:** Unauthorized users can access it.              | Protects user privacy and ownership evidence.       |
| **NFR-2** | Performance        | Process matching and display potential matches within the defined response-time target under normal and peak load.           | High     | **Pass:** Matching meets the response-time target under simulated load.<br>**Fail:** Processing consistently exceeds the target. | Timely matching improves recovery chances.          |
